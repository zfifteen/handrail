HR-CR-20260509-001: iPhone follow-up composer permits duplicate submissions while one is pending

iOSOpen
ios/Handrail/Handrail/Views/ChatDetailView.swift:31 ios/Handrail/Handrail/Views/ChatDetailView.swift:355 ios/Handrail/Handrail/Views/ChatDetailView.swift:370 ios/Handrail/Handrail/Views/ChatDetailView.swift:466
Logical failureThe phone follow-up path sets pendingContinuePrompt, but the shared composer disables only when pendingSendInput is non-nil. A completed chat can therefore send the same follow-up repeatedly before the transcript echoes the prompt.
Observable consequenceCodex Desktop can receive duplicate follow-up turns, causing repeated work, confusing transcript state, and extra approval or stop events tied to the same user intent.
Minimal remediationDisable the shared composer on the relevant pending state, or pass an explicit isPending value into composer so follow-up uses pendingContinuePrompt and direct-input uses pendingSendInput.
VerificationAdd a Swift unit or view-model test that sends a follow-up, asserts the send control disables while pendingContinuePrompt is set, and re-enables after the transcript contains the prompt or an error arrives.

HR-CR-20260509-004: New approval panels can inherit stale Approved or Denied state from a previous approval

iOSOpen
ios/Handrail/Handrail/Views/ChatDetailView.swift:12 ios/Handrail/Handrail/Views/ChatDetailView.swift:253 ios/Handrail/Handrail/Views/ChatDetailView.swift:264 ios/Handrail/Handrail/Views/ChatDetailView.swift:319
Logical failureapprovalResultText is a view-wide string, not keyed to the current approval. Once set to Approved or Denied, the next approval rendered by the same ChatDetailView can display that old result before the user acts.
Observable consequenceA fresh approval can appear already approved or denied, which is a high-risk supervisory error for a local remote-control app.
Minimal remediationStore the result with the composite approval identity and display it only when the visible approval matches. Clear the local result when latestApproval changes to a different chatId/approvalId.
VerificationAdd a test or preview-state check that renders approval A, approves it, then renders approval B in the same chat view and asserts no prior result label is visible.
