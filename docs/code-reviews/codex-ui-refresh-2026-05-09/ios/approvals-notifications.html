HR-CR-20260509-002: Approval identity is not consistently scoped by chat on iOS

iOSOpen
ios/Handrail/Handrail/Models/HandrailModels.swift:165 ios/Handrail/Handrail/Stores/HandrailStore.swift:300 ios/Handrail/Handrail/Stores/HandrailStore.swift:311 ios/Handrail/Handrail/Views/IPad/IPadApprovalReviewWorkspaceView.swift:162
Logical failureApprovalRequest.id is approvalId alone and notification approval/deny cleanup clears latestApproval by matching approvalId without also matching chatId.
Observable consequenceIf Codex Desktop reuses request identifiers across chats, an action on one chat can clear or render the pending approval for another chat. This violates the branch goal of chat-scoped approval routing.
Minimal remediationUse a composite approval identity everywhere on iOS, for example "chatId approvalId", and require both chatId and approvalId when clearing latestApproval or resolving selected approvals.
VerificationAdd iOS tests with two ApprovalRequest values sharing approvalId and different chatId, then assert notification approval/deny and selection logic affect only the matching chat.

HR-CR-20260509-003: Local notifications are suppressed when the app is backgrounded

iOSOpen
ios/Handrail/Handrail/Utilities/NotificationCoordinator.swift:215 ios/Handrail/Handrail/Utilities/NotificationCoordinator.swift:217 ios/Handrail/Handrail/Stores/HandrailStore.swift:391 ios/Handrail/Handrail/Stores/HandrailStore.swift:425
Logical failureschedule returns unless UIApplication.shared.applicationState is .active. That condition prevents local notification requests from being added while the app is inactive or backgrounded.
Observable consequenceThe user is least likely to receive local approval, input-required, failed, or completed notifications when they most need them: while Handrail is not foregrounded.
Minimal remediationInvert the decision model: suppress in-app banners only for the currently viewed chat, but allow UNUserNotificationCenter scheduling when the app is backgrounded. Keep remote-push policy separate from local notification scheduling.
VerificationAdd a notification coordinator test seam or integration harness that simulates background state and verifies a notification request is still enqueued for an unseen chat.
