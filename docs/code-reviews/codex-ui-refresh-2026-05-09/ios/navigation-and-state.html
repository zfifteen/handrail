HR-CR-20260509-008: Phone notification routes append duplicate chat-detail destinations

iOSOpen
ios/Handrail/Handrail/Views/RootView.swift:42 ios/Handrail/Handrail/Views/RootView.swift:99 ios/Handrail/Handrail/Views/RootView.swift:152 ios/Handrail/Handrail/Views/RootView.swift:158
Logical failureEvery phone route event appends chatId to NavigationPath without checking whether that chat is already the top destination.
Observable consequenceRepeated taps on a notification for the same chat can build a stack of identical ChatDetailView instances. Back navigation then appears to revisit the same screen repeatedly.
Minimal remediationTrack the current phone chat route or reset/replace the path before appending notification-driven chat destinations.
VerificationAdd a RootView route test that sends the same PhoneRootRoute twice and asserts only one detail destination is present.
